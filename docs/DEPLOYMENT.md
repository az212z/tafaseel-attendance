# نشر التطبيق وربطه بالمركز

التطبيق مستقل بواجهته ورابطه، ويحتاج الوصول إلى ملف SQLite الحالي على **الاستضافة نفسها**. استضافة واجهة أخرى منفصلة لا تتيح الوصول الآمن إلى الملف وحدها؛ ستحتاج وقتها API خلفية إضافية. هذا الإصدار مجهز للاستضافة الحالية باستخدام كود PHP المشترك.

## التحقق من المصدر

وُجد المستودعان `az212z/tafaseel-training` و`az212z/tafaseel-training-center`. الأول نسخة Vite/Supabase أقدم، والثاني نسخة Next.js ثابتة. الدومين الحالي يقدّم Next.js مع API من `/api/`، وكتالوج من ٢٠ دورة. وُجدت نسخة محلية أحدث في مجلد `hostinger-site` للمشروع السابق، تحتوي `server/app.php` الإصدار 1.5.1 وجداول SQLite. طابق ملفان عامّان من ملفات الموقع ملفات البناء المحلية، لكن هذا لا يثبت تطابق كود PHP الخاص على الخادم. ينبغي تنزيل نسخة كود الخادم ومراجعة الإصدار والمخطط قبل التثبيت.

النسخة الموجودة في `integration/tafaseel-core` من هذه الملفات العامة المصدر محليًا تستخدم للاختبارات فقط. لا تنسخ معها أي `config.php` أو قاعدة فعلية. كود الإنتاج للحضور يستدعي `app.php` الموجود أصلًا على الاستضافة، ولا يستبدله.

## ملفات الاستضافة

اقتراح الرابط: `attendance.tafaseel-training.com`، بشرط إعداد النطاق الفرعي وHTTPS. هذا الرابط **لم يُنشأ بعد**.

مثال لتنظيم الملفات عند كون الجذر العام والملفات الخاصة مجلدين متجاورين:

```text
domain-directory/
  public_html/          # واجهة تطبيق الحضور فقط
    index.html
    assets/
    api/index.php
    .htaccess
  attendance-private/   # خارج الجذر العام
    config.php
    bootstrap.php
    attendance.php
    schema.sql
    migrate.php
    cron.php
```

داخل `attendance-private/config.php`، ابدأ من `config.example.php`:

- `legacy_dir`: المسار الحقيقي لمجلد `tafaseel-private` للموقع الأساسي، وهو يحتوي `app.php` و`config.php` الحاليين. لا تستبدل إعدادات الموقع أو قاعدة بياناته.
- `origin`: رابط تطبيق الحضور النهائي، HTTPS، بلا شرطة في النهاية.
- `preview`: يظل `false` في الإنتاج.
- `sms_enabled`: يبدأ `false` حتى اكتمال إعداد المزوّد.
- `sms_provider`: `taqnyat` للمحوّل المضمّن؛ المزوّد الآخر يحتاج محوّلًا مطابقًا لتوثيقه.
- `sms_token` و`sms_sender`: يضبطهما مسؤول الاستضافة خارج الجذر العام، أو في متغيرات البيئة. لا يوضع المفتاح في الواجهة أو Git أو المحادثة.

يشير `public_html/api/index.php` افتراضيًا إلى المجلد الخاص المجاور للجذر العام. إذا كان النطاق الفرعي داخل جذر متداخل، اضبط `ATTENDANCE_PRIVATE_DIR` إلى المسار الفعلي، أو عدّل مسار المجلد الخاص في هذا الملف. يجب إبقاء الملفات الخاصة وقاعدة البيانات خارج أي مجلد يقدم ملفات للإنترنت.

كلٌّ من الدومين الأساسي وتطبيق الحضور يجب أن يمتلك صلاحية نظام الملفات للوصول إلى قاعدة البيانات الحالية. إن منعت `open_basedir` ذلك، استخدم جذر نطاق فرعي داخل نطاق الاستضافة نفسه مع مجلد خاص خارج الجذر العام؛ لا تجعل ملف SQLite متاحًا عبر HTTP.

## التثبيت

1. راجع نسخة PHP الحالية والمخطط، وخذ نسخة مستقلة متسقة من قاعدة البيانات وإعداداتها.
2. أنشئ النطاق الفرعي واربط HTTPS والجذر العام لتطبيق الحضور. لا ترفع مجلد المصدر كاملًا فوق موقع المركز.
3. ابنِ الحزمة بـ`npm run package`. فك `public_html` داخل جذر الحضور فقط، و`attendance-private` خارج الجذر العام.
4. جهز `config.php` الخاص بالحضور مع `legacy_dir` الصحيح و`origin` النهائي. لا تستخدم إعداد التجربة.
5. نفّذ من طرفية الاستضافة:

```sh
/usr/bin/php /ABSOLUTE/PATH/attendance-private/migrate.php
```

ينشئ المثبّت نسخة احتياطية متحققة عبر خدمة النسخ الأصلية قبل إضافة جداول الحضور. إذا تعذر النسخ يتوقف التثبيت. الترحيل يضيف جداول وفهارس ومشغل حذف خاص بسجلات الحضور؛ لا يستورد ولا يستبدل الدورات والطلاب.

6. سجّل الدخول بحساب مدير المركز الموجود أصلًا. جلسة الدخول على النطاق الفرعي مستقلة، بينما الحساب وكلمة المرور من القاعدة نفسها.
7. قارن أعداد الدورات والطلاب وتسجيلًا تجريبيًا متفقًا عليه في اللوحتين. راجع العرض والطباعة من الحاسوب، وQR من هاتف فعلي على HTTPS.
8. أضف رقم ولي الأمر وموافقته، وجهز رمز حضور الطالب وسلّمه له بشكل خاص. أنشئ حصة مستقبلية من المجموعة الصحيحة. حدّث قائمة الحصة بعد أي تغيير في تسجيلاتها من الموقع الأساسي وقبل بدايتها.

## الرسائل والتشغيل المجدول

المحوّل يتبع [توثيق تقنيات الرسمي](https://dev.taqnyat.sa/ar/doc/sms/): Bearer في ترويسة الخادم، واسم مرسل معتمد، ورقم دولي بلا `+` في الحمولة. استخدم حساب المركز واسم مرسل صالحًا لديه. لا يُدرج المفتاح في روابط QR أو بيانات المتصفح.

بعد تهيئة الحساب واختبار رسالة إلى رقم اختبار معتمد، فعّل `sms_enabled=true`، ثم أضف مهمة كل دقيقة في Hostinger:

```sh
/usr/bin/php /ABSOLUTE/PATH/attendance-private/cron.php
```

المهمة CLI فقط، ولا يوجد لها رابط HTTP لتشغيل الإرسال. تحافظ على قفل بين النسخ المتزامنة، وتعيد فحص الطالب قبل إرسال كل رسالة. قارن «آخر تشغيل» في حالة الربط وسجل مزوّد الرسائل. استمرار إغلاق لوحة المدير لا يوقف المهمة.

«قبله المزوّد» ليست إيصال وصول. المهلة أو انقطاع العامل أثناء إرسال طلب تجعل النتيجة غير مؤكدة. لا إعادة تلقائية لتلك الرسالة؛ راجع المزوّد قبل أي إجراء يدوي. نسخة المعاينة تمنع إرسال SMS ولو أُدخلت إعدادات المزوّد بالخطأ.

## النسخ والتراجع

نسخ الموقع الأساسي المتسقة لملف SQLite تشمل جداول الحضور أيضًا. لا تضف مهمة استعادة أو نسخ جديدة فوق المهمة القائمة قبل مراجعتها. لإيقاف الإرسال: عطّل مهمة الحضور و`sms_enabled`؛ يستمر الموقع الأساسي. لا تحذف الجداول عند التراجع عن الواجهة، حتى يبقى التاريخ محفوظًا.

حذف الطالب النهائي من التطبيق الأساسي يحذف ملف الحضور وسجل رسائله المرتبط به بواسطة المفاتيح الخارجية، وينظف آثار ملاحظاته في سجل عمليات الحضور. اختُبر هذا باستخدام نسخة معزولة من API الأساسية، وليس على طلاب حقيقيين.
