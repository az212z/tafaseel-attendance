# حضور تفاصيل

## نسخة GitHub للاختبار

رابط التجربة: https://az212z.github.io/tafaseel-attendance/

اضغط «دخول النسخة التجريبية». نسخة Pages تفاعلية وتحفظ الطلاب والحصص والحضور في متصفحك فقط، مع بيانات مصطنعة في البداية. لا تتصل بقاعدة المركز، ولا تطلب بيانات دخول المدير الحقيقية، ولا ترسل SMS. تنبيهات الغياب فيها موسومة «محاكاة فقط»، وتُراجع أثناء فتح الصفحة.

من بطاقة QR افتح «صفحة الطالب»: رقم التسجيل `1` ورمز التجربة `24681357`. بيانات الحصص والطلاب التي تضيفها لا تنتقل إلى جهاز أو متصفح آخر. عرض QR والطباعة والتصدير يعمل؛ اختبار حضور حصة جديدة يكون من صفحة الطالب في المتصفح الذي أنشأها. يُستخدم ربط الخادم أدناه لاحقًا للتشغيل الحقيقي بين الأجهزة.

لإعادة بناء نسخة Pages: `npm run build:demo`. لفحصها: `npm run test:demo`. النشر الآلي في `.github/workflows/pages.yml` يرفع الواجهة فقط ويستبعد ملفات PHP وإعدادات الخادم.

تطبيق مستقل لإدارة حضور وانصراف طلاب مركز تفاصيل، مجهز للاتصال بقاعدة بيانات الموقع الحالية على Hostinger. يستعمل جداول `students`, `courses`, `cohorts`, `registrations`, `users` نفسها، ويضيف جداول الحضور فقط.

**حالة ربط المركز:** لم يُنشر التطبيق على استضافة المركز، ولم تُعدّل قاعدة بياناته الفعلية، ولم تُرسل رسالة SMS فعلية. نسخة PHP المحلية مجهزة للربط؛ يجب التحقق من نسخة الخادم ومسارها قبل التثبيت.

## التجربة المحلية

يتطلب Node.js 22.12+، وPHP 8.3+ مع SQLite3 وmbstring وcURL، وPython 3.

```sh
npm ci
npm start
```

افتح http://127.0.0.1:3080 واضغط «دخول النسخة التجريبية». توجد ٨ ملفات طلاب مصطنعة، والدورات العشرون من كتالوج المشروع، وحصتان توضيحيتان. لا تُنسخ قاعدة المركز أو كلمة مرور مديره إلى التجربة. الدخول التجريبي محصور بالبيئة المحلية على loopback، وبإعداد منفصل لا يُضمّن في النشر.

من بطاقة الرمز، افتح «صفحة الطالب» أو «عرض الرمز للكلاس». رمز الطلاب التجريبي `24681357`، وأرقام التسجيل في قائمة الطلاب. تُنشأ كلمة مرور مدير التجربة عشوائيًا وتُحفظ خارج مجلد الموقع. الرمز QR المحلي يعمل على الجهاز نفسه؛ يحتاج مسح الجوال إلى رابط HTTPS منشور.

## الوظائف

- إنشاء حصة باسمها وموعدها والمجموعة المرتبطة بها، مع QR خاص بالحصة والتاريخ وعرض للطباعة.
- قراءة الدورات والمجموعات والطلاب من الجداول المشتركة، وإضافة طالب وتسجيله في مجموعة. عند اكتمال ٢٠ مقعدًا يذهب إلى الانتظار وفق سعة النظام الأساسي.
- رقم تسجيل ورمز حضور عشوائي من ٨ أرقام لكل طالب؛ يُخزن الرمز مجزأً، ويظهر للإدارة مرة واحدة عند إنشائه أو تجديده. لا يكفي إدخال الاسم.
- حضور وانصراف منفصلان، حضور متأخر، غياب بعذر، تعديل إداري بسبب محفوظ، وتصدير CSV.
- يفتح الحضور قبل البداية بـ١٥ دقيقة وحتى ٣٠ دقيقة بعد النهاية، ويفتح الانصراف قبل النهاية بـ١٥ دقيقة.
- يبدأ فحص الغياب بعد ٢٠ دقيقة من وقت الحصة المحفوظ على الخادم بتوقيت الرياض. لا يعتمد الفحص على بقاء المتصفح مفتوحًا.
- إشعار غياب واحد لكل طالب وحصة في سجل دائم. يعيد العامل فحص التسجيل والإعفاء والحضور قبل الإرسال. يُلغى التنبيه الذي لم يُرسل عند حضور الطالب متأخرًا أو إغلاق الحصة.
- عنوان ولي الأمر ورقم جواله وموافقته منفصلة عن جوال التواصل القديم. لا يُفترض أن جوال الطالب هو جوال ولي الأمر.
- ربط خادم جاهز لمزوّد تقنيات عبر [واجهته الرسمية](https://dev.taqnyat.sa/ar/doc/sms/)، مع فصل قبول المزوّد عن وصول الرسالة فعليًا. لا يعمل حتى توفير حساب ومفتاح واسم مرسل وتفعيل إعداد الإرسال.

تُثبت قائمة الحصة عند إنشائها. الإضافات من تطبيق الحضور تُلحق بالحصص القادمة للمجموعة. بعد إضافة أو نقل طالب من الموقع الأساسي، اضغط «تحديث الطلاب» في سجل الحصة قبل بدايتها. بعد البداية تبقى القائمة ثابتة، مع استبعاد التسجيل الملغى أو المنقول من التنبيهات. تحديثات البيانات الأساسية تظهر عند إعادة التحميل أو خلال التحديث الدوري.

## الاختبارات والبناء

```sh
npm test
npm run typecheck
npm run build
npm run package
```

الاختبارات تنشئ قاعدة SQLite مؤقتة معزولة. تشمل المصادقة وCSRF وOrigin، مشاركة البيانات، الأرقام العربية، الحضور والانصراف ومهلتهما، مهلة الـ٢٠ دقيقة الدقيقة، منع تكرار الصف، الاستبعاد والإلغاء، تفسير نتيجة SMS، وتوافق حذف الطالب من النظام الأساسي مع جداول الحضور. لا تستدعي مزود SMS فعليًا.

حزمة النشر: `output/tafaseel-attendance-deploy.zip`. تحتوي مجلدًا عامًا ومجلد PHP خاصًا؛ لا تحتوي بيانات طلاب أو ملفات إعداد فعلية أو كلمات مرور. المصدر المرجعي في `integration/tafaseel-core` للاختبارات فقط، ولا يُرفع بدل كود الموقع المنشور.

تعليمات الربط على الاستضافة: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md). نتائج التحقق: [docs/QA.md](docs/QA.md).

## حدود تشغيل مهمة الرسائل

فحص كل دقيقة يعني تجهيز التنبيه بين الدقيقة ٢٠ والدقيقة ٢١ في التشغيل الطبيعي. عند توقف المهمة لا تُرسل تنبيهات قديمة بعد نهاية الحصة. عند تعطيل المزوّد تُسجل الحالة «يتطلب استكمالًا» ولا تُحسب رسالة مرسلة. إذا انقطع الاتصال بعد احتمال قبول الرسالة، تصبح الحالة «تحتاج مراجعة» ولا يُعاد الإرسال تلقائيًا تفاديًا للتكرار؛ يجب مراجعة سجل المزوّد. لا توجد إعادة محاولة تلقائية للحالات المرفوضة أو غير المؤكدة في هذه النسخة.

الرمز مخصص للحصة ويمكن مشاركته؛ ليس إثبات موقع جغرافي. التحقق هنا برقم تسجيل الطالب ورمزه الخاص، دون طلب صلاحية موقعه أو كاميرته من التطبيق. يمكن استخدام كاميرا الجوال المعتادة لفتح QR.
